# FinTrack v1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task (inline — parallel subagents are banned on this machine, see user memory). Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Android-only local-first finance tracker that auto-captures bank SMS into categorized expenses with budgets, insights, recurring tracking, and CSV/PDF export.

**Architecture:** Flutter UI + Drift (SQLite) storage; `another_telephony` background Dart isolate receives SMS, a pure-Dart parser table extracts transactions, `flutter_local_notifications` posts actionable categorize notifications. All parsing shared between live receive and history import. No network.

**Tech Stack:** Flutter stable, Drift, riverpod, another_telephony, flutter_local_notifications, fl_chart, pdf+printing, csv, share_plus.

## Global Constraints

- All data on-device; zero network calls; no analytics.
- Money is integer paise everywhere (`int amountPaise`); floats never touch money.
- Cashew = design inspiration only; never copy its code (unlicensed).
- Kotak + Indian Bank patterns UNVERIFIED (drafted); ICICI debit pattern verified from real sample. Unmatched bank SMS → review queue, never dropped.
- Package versions: resolve with `flutter pub add <pkg>` (latest compatible), don't hand-pin from memory.
- ANDROID_HOME=/opt/homebrew/share/android-commandlinetools; JDK temurin@21.
- Every task ends: `flutter analyze` clean + tests pass + commit.

### Task 3: SMS parser (TDD, core IP)

**Files:** Create `lib/parser/parsed_txn.dart`, `lib/parser/patterns.dart`, `lib/parser/sms_parser.dart`, `test/parser_test.dart`.

**Interfaces:**
- `ParsedTxn { int amountPaise; Direction direction; String merchant; String? accountTail; DateTime txDate; String? ref; String bank; }`
- `SmsParser.parse(String sender, String body, {DateTime? received}) → ParsedTxn?` (null = not a transaction)
- `SmsParser.isBankSender(String sender) → bool` (matches DLT sender IDs like `XX-ICICIB-S`, `AD-KOTAKB`, `.*INDBNK.*` etc — suffix/infix match on ICICIB|ICICIT, KOTAKB|KOTAKM, INDBNK|INDBK)

**Verified pattern (ICICI UPI debit), test must use this exact sample:**
```
ICICI Bank Acct XX106 debited for Rs 55.00 on 06-Jul-26; PRAVEEN R V credited. UPI:655315924126. Call 18002662 for dispute. SMS BLOCK 106 to 9215676766.
```
regex: `ICICI Bank Acct XX(\d+) debited for Rs ([\d,]+\.?\d{0,2}) on (\d{2}-\w{3}-\d{2}); (.+?) credited\.(?: UPI:(\d+))?`
→ amountPaise 5500, debit, merchant "PRAVEEN R V", tail "106", date 2026-07-06, ref "655315924126".

**Drafted patterns (mark UNVERIFIED in code comments):** ICICI credit (`credited with Rs`), ICICI card spend (`spent on ICICI Bank Card`), Kotak debit (`Sent Rs.X from Kotak Bank AC XNNNN to ... on DD-MM-YY.UPI Ref NNN`), Kotak credit (`Received Rs.X in your Kotak Bank AC`), Indian Bank debit/credit (`Rs. X debited/credited A/c *NNNN ... UPI/P2P/ref`). Date formats: `dd-MMM-yy`, `dd-MM-yy`, `dd/MM/yyyy` — helper `parseIndianDate`.

**Negative tests (must return null):** OTP SMS ("OTP is 482913"), promo ("Get 10% cashback"), balance enquiry ("Avl Bal"), non-bank sender with amount-like text.

**Steps:**
- [ ] Failing tests (all samples above) → implement patterns table + parser → tests pass.
- [ ] Amounts: strip commas, `Rs`/`Rs.`/`INR`/`₹` variants; paise via `(rupees*100 + paise)` integer math, no double.
- [ ] Commit `feat: sms parser with verified icici pattern + drafted kotak/indian bank`.
